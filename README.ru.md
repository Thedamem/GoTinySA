# tinysa_go

[English](README.md) | **Русский**

tinysa_go — настольное приложение для анализаторов спектра **tinySA** и **tinySA Ultra** на Go с интерфейсом Wails/Svelte. Это порт [QtTinySA](https://github.com/g4ixt/QtTinySA): функциональность оригинала сохранена, а последовательный порт, разбор свипов, логирование и работа с файлами вынесены из потока интерфейса.

Приложение собирается в один бинарник для Linux и Windows. Встроенный HTTP-сервер даёт отдельный интерфейс для телефона, чтобы настраивать антенну из той же локальной сети.

## Возможности

- Подключение tinySA и tinySA Ultra по USB CDC, поиск портов и диагностика.
- Живой спектр и водопад на canvas, трассы max/avg/min, зум/пан и подсказка по точке.
- Управление свипом: start/stop/center/span, точки, RBW auto/manual, аттенюатор auto/manual, LNA и Spurs.
- Частота и уровень пика, медианный шум, SNR и max-hold.
- Экспорт текущего свипа в CSV.
- Сырой USB-лог (текст и бинарник) для диагностики и повторного разбора.
- `tinysa-cli` для списка портов и команд прибору без GUI.
- Веб-интерфейс для телефона: живой спектр, водопад, показания, пресеты диапазонов, настройки свипа и CSV.
- Два языка интерфейса: английский (по умолчанию) и русский.

## Требования

- Go 1.25 или новее
- Wails CLI v2.17
- Node.js и npm
- Linux GUI-зависимости: `libgtk-3-dev libwebkit2gtk-4.1-dev`
- tinySA или tinySA Ultra, подключённый по USB, для измерений

## Сборка

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.0

wails build -tags webkit2_41          # Linux
wails build -platform windows/amd64   # кросс-сборка Windows
```

Для разработки:

```sh
wails dev -tags webkit2_41
```

`npm run dev` без Wails поднимает только Vite; Go-биндинги в этом режиме не работают.

Каталог `frontend/dist` закоммичен и встраивается в Go-бинарник. После изменений фронтенда выполните `npm run build` в `frontend/` или дайте `wails build` пересобрать его.

## Веб-интерфейс для телефона

1. Подключите анализатор и запустите приложение.
2. Откройте **Web** и нажмите **Включить**. Диалог покажет текущий LAN-адрес и QR-код.
3. Откройте адрес на телефоне в той же Wi-Fi сети.
4. В телефонном интерфейсе доступны спектр, водопад, пик/шум/SNR, пресеты диапазонов, start/stop/span, точки, RBW, аттенюатор, LNA, Spurs, трассы и CSV.
5. **Пик в центр** и **Зум на пик** перестраивают диапазон вокруг сильного сигнала. **Применить** перезапускает свип с новыми настройками.

Сервер слушает `0.0.0.0:8420` (если порт занят — свободный) и **не имеет пароля**. Используйте его только в доверенной локальной сети и не открывайте порт в интернет. Сервер работает только пока открыто приложение.

Если Wi-Fi не достаёт до антенны, включите точку доступа на телефоне и подключите ноутбук к ней. Адрес веб-интерфейса останется тем же, поменяется только IP; актуальный адрес показывает диалог **Web**.

## Язык

Интерфейс приложения и телефонной страницы доступен на английском и русском языках.

- Десктоп: **Настройки → Язык → Русский** (в английской локали — **Settings → Language**).
- Телефон: переключатель **EN / RU** в шапке.

Выбор сохраняется локально в webview или браузере и не отправляется на прибор.

## CLI

`tinysa-cli` использует тот же serial-слой, что и GUI, и удобен для диагностики:

```sh
go run ./cmd/tinysa-cli -list
go run ./cmd/tinysa-cli -port /dev/ttyACM0 version
```

В Windows используйте COM-порт, например `-port COM5`.

## Проверки

```sh
cd frontend && npm ci && npm run build
go vet -tags webkit2_41 ./...
go build -tags webkit2_41 ./...
go test -tags webkit2_41 -race ./...
```

Тесты используют фейковые serial-порты и backend; железо не требуется.

## CI и релизы

GitHub Actions выполняет проверки в `.github/workflows/ci.yml` и собирает артефакты Linux и Windows в `.github/workflows/build.yml`. Теги `v*` публикуют релиз с приложением и бинарниками `tinysa-cli`.

## Windows: USB-устройство не найдено

1. Кабель должен быть с линиями данных, а не только для зарядки.
2. В **Диспетчере устройств → Порты (COM и LPT)** прибор должен появиться как COM-порт (`tinySA` / `USB Serial Device`). Windows 10/11 ставит драйвер usbser автоматически.
3. Убедитесь, что порт не занят: QtTinySA, терминал или вторая копия приложения.
4. Диагностика без GUI: `tinysa-cli.exe -list` покажет порты; `tinysa-cli.exe -port COM5 version` проверит связь. В приложении: **Настройки → Отладка… → Показать порты** (в английской локали — **Settings → Debug…**).

## Структура проекта

- `app.go`, `web.go`, `main.go` — Wails-приложение, десктопный API и встроенный веб-сервер.
- `internal/serial` — последовательный транспорт, владение портом, фрейминг и сырой лог.
- `internal/tinysa` — протокол, парсер свипов, трассы и CSV.
- `internal/webui` — HTTP/SSE-сервер и ресурсы телефонного интерфейса.
- `frontend/` — Svelte-интерфейс десктопа и Wails-биндинги.
- `cmd/tinysa-cli` — диагностика из командной строки.
- `docs/` — заметки по протоколу, референсу, функциям и UI.
